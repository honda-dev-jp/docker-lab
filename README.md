# docker-lab

Webアプリケーションの開発・検証に使用する Docker 環境を、構成ごとに管理するリポジトリです。

Dockerfile、Docker Compose 設定、環境ごとの構築・検証手順を整理し、アプリケーション本体と開発環境を分離して管理します。特定の教材やアプリケーションに依存しない、再利用可能な構成を目指します。

> **用途:** ローカル開発・技術検証向けです。記載された設定を、そのままインターネット公開用の本番環境に使用することは想定していません。

## リポジトリ構成

```text
docker-lab/
├── README.md          # リポジトリ全体の概要
├── SECURITY.md        # セキュリティ方針・脆弱性報告方法
└── lamp/              # PHP / Apache / MySQL 開発環境
    ├── README.md      # LAMP 環境の構築・操作・検証手順
    ├── Dockerfile
    ├── docker-compose.yml
    ├── .env.example
    ├── .gitignore
    ├── php.ini
    ├── apache/
    └── mysql/
```

新しい技術スタックは原則として独立したディレクトリへ追加し、既存環境への意図しない影響を避けます。

## 使い始める前に

- Docker Engine および Docker Compose（`docker compose` コマンド）を使用できること。
- 使用する環境の README を先に読み、必要なポート・データ保存先・ホスト固有の条件を確認すること。
- `.env.example` がある場合はローカル用の `.env` を作成し、テンプレート値を本物のパスワードとして使用しないこと。
- アプリケーション本体など、別リポジトリへの bind mount がある環境では、参照先の準備が別途必要です。

### LAMP 環境

LAMP 環境のセットアップ・起動・停止・トラブルシューティングは **[lamp/README.md](lamp/README.md)** を参照してください。

基本的な操作を行う場所は `lamp/` です。

```bash
cd lamp

# 事前準備と .env の設定を終えた後、構文を検証する
# （設定値全体を表示しない）
docker compose config --quiet

# 環境を起動する
docker compose up -d --build

# 稼働状態を確認する
docker compose ps

# コンテナを停止・削除する（名前付きボリュームは保持）
docker compose down
```

**注意:** これは操作の概要です。最初の起動前に、[詳細なセットアップ手順](lamp/README.md#初回セットアップ)にある `.env`、別リポジトリの配置、ホスト固有の設定を確認してください。

現在の LAMP 構成では Web と phpMyAdmin のポートを `127.0.0.1` にバインドし、MySQL のポートはホストへ公開していません。実際の公開範囲は設定を変更するたびに再確認してください。

## 設計・運用方針

- **環境ごとに分離:** Docker 関連設定はディレクトリ単位で管理します。アプリケーション本体は必要に応じて別リポジトリに置き、bind mount で参照します。
- **再現性:** 使用する技術の公式ドキュメントとサポート状況を確認し、更新時には影響範囲と互換性を検証します。
- **ローカル公開を最小化:** ホストへのポート公開は必要最小限とし、ローカル用途では原則 `127.0.0.1` に限定します。
- **秘密情報を保護:** `.env`、秘密鍵、認証情報、バックアップ、実データ、ホスト固有の非公開設定はコミットしません。Git に登録するのはダミー値のテンプレートに限定します。
- **検証してから変更:** 依存関係やイメージのアップグレードは、脆弱性・破壊的変更・依存経路を確認し、関連する動作検証を経て反映します。
- **Issue と PR で追跡:** 変更内容と確認結果を Issue / Pull Request に記録する運用を基本とします。

脆弱性に関する報告方法は [SECURITY.md](SECURITY.md) を参照してください。

## 更新・セキュリティについて

GitHub の依存関係アラート等は、検出や通知を補助する仕組みです。Docker イメージ内の OS パッケージ、実行時設定、アプリケーション固有の問題まで網羅するものではありません。

脆弱性の対応は、内容と影響範囲を確認したうえで手動で判断・修正し、必要なテストとレビューを行います。最新の設定・保護機能の状態は、リポジトリの GitHub 設定画面を正本とします。
